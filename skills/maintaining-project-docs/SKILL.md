按用户指定的主题或范围工作。请求审阅时，给出有证据的发现和建议。请求整理时，直接完成能核实的修订；只有需要决定产品意图或取舍唯一资料时才询问。沿用仓库已有的术语、文档分工和保留约定。

1. **沿任务找入口。** 从维护者或接手的 agent 要完成的任务出发，顺着入口读到操作步骤、现行规则和历史理由。列出范围内各主题由哪一页负责，注意散落在其他目录的同一主题。查找文档的读者，也查找读取这些文件、标题或段落的程序和测试。
2. **给说法找证据。** 对照配置、代码、测试或带日期的验收记录，核对现行文档里的数值、命令、前置条件和状态。分别找出作出决定、完成实现、实际部署的依据。记录哪一处说法与哪份证据冲突；若实现可能偏离仍有效的约定，保留双方依据，把意图交给用户判断。
3. **按主题收拢。** 把现行说明放在负责该任务的页面，其他入口链接过去。容易查到且会变化的值尽量指向其维护位置。压缩旧报告时提取仍影响判断的结论、适用条件、失败经验和证据位置。保留 ADR 的决定、理由和后继关系。退役原文前核实原本内容可从具体 Git 版本或项目档案找回，包括检查尚未提交的独有内容。
4. **从入口重新走一遍。** 沿操作说明走到读者实际复制或执行的文件，核对其中的注释和示例是否与入口一致。检查受影响的引用、标题锚点、程序读取边界和操作示例的前置条件，复用仓库已有的验证方式。以读者能从入口找到并完成任务为准。审阅时按对读者任务的影响排列发现，优先列出会导致误操作、误判当前状态或破坏程序读取的问题，每项给出具体位置、证据和最小修订建议。整理结果说明改了什么、如何验证，以及哪些判断仍缺证据。
